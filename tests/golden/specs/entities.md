# Entities

`pc-retail-v3.0e/entities_retail.tsv` has one row for every final `FROG` map in
the supported v3.0e archive. It records the map resource and name, total entity
count, generic `STATIC` and `MOVING` counts, and the count accepted by base
entity setup. The remaining columns are [list digests](../README.md#digest-convention)
of decoded integer facts. An empty list uses `-`.

`identity_digest` flattens every source ordered entity as `(index, source offset,
end offset, form grid id, unique id, form id, flags, EXE entity type, EXE script
id, EXE collision callback, EXE bonus callback)`. Missing forms use `-1` for
the four EXE fields. `base_record_digest` flattens generic `STATIC` entities as
`(index, 0, matrix[0..8], translation[0..2])` and generic `MOVING` entities as
`(index, 1, path id, segment id, segment distance, authored motion flags, speed)`.
The matrix is row major fixed12 rotation plus whole unit translation. Its
stored 16 bit pad and the PATH_INFO alignment pad are omitted from the digest;
the latter must be zero for setup acceptance. `setup_digest` flattens each
accepted `(index, unique id)`. Unknown behavior, unsupported alignment flags,
invalid path geometry or start, malformed PATH_INFO padding, and unknown flags
are omitted from setup but remain in the total identity count.

The generator follows FrogLord's `FroggerMapFilePacketEntity`,
`FroggerMapEntity`, `FroggerEntityDataMatrix`, `FroggerPathInfo` and
`PSXMatrix` layouts. It independently reads the owner's EXE form libraries,
FrogLord name configuration and MWD. It never writes source bytes to the
golden file. Regenerate with:

```powershell
python -B tools/make_golden_entities.py --data-dir C:\Users\janit\Desktop\repos\froggy\resources\pc-version\extracted\FROGGER --out-dir tests\golden\pc-retail-v3.0e
```

`fixtures/entities.json` contains invented source ordered entity definitions.
Moving entities reference an invented case in `fixtures/paths.json` or provide
inline path segments. `synthetic/entities_trace.tsv` records tick zero and each
later tick with entity index, unique id, full matrix, and all fourteen path
snapshot values. Static entities use fourteen `-1` fields for the absent path.
The independent Python evaluator implements frozen `PATH.C` and generic entity
update math; before writing a trace, it requires exact agreement with
`entity_oracle_adapter.c`. That adapter calls unchanged frozen
`ENTSTRUpdateMovingMOF` and path functions and runs all paths before entity
transforms. The component reset applies authored flags before tick zero, so it
intentionally does not use the fresh live entity creation tangent. Build and
regenerate with external compiler output:

Cases cover static transforms, world alignment, ordinary orientation from
diagonal and vertical lines, zero tangent, arc and spline tangents, shared paths
with different speeds, `NO_MOVEMENT`, backwards starts, and one shot/repeat
endpoints. Generic forms can also have scripts and callbacks; this component
leaves them unexecuted and does not claim complete entity behavior. Local
alignment and land projection are outside this component's scope.

### Animated primitive contacts

`synthetic/entity_animated_primitives.json` (schema
`entity-animated-primitives-v1`) is generated by
`tools/make_golden_entity_animated_primitives.py`, an independent Python
reading of frozen `MR_COLL.C` `MRCheckCollPrimWithWorldPoint` and `MR_ANIM.C`
stored LW transforms. It contains no retail data apart from the plant's
103-sine primitive rotation. Each of the 67 `cases` supplies a frog root,
frog part matrix12 and vertex; an entity root and one primitive-part frame
(matrix12); and a primitive with `offset`, `half_size`, `flags` and `matrix`
(twelve values whose non-zero translation the source ignores, or empty for no
matrix). Expected values are the frog `world` point, the stored `lw` (rotation
`MRMulMatrixABC` with signed32 sums shifted by 12 and stored as shorts; part
translation rotated by the root and added), the collision `rotation` (`lw`
times the primitive matrix, or `lw` alone), the signed16 `delta` from the
`lw`-rotated offset, the `local` vector (transposed rotation times `delta`)
and the strict `hit`. Named cases cover a matrix-rotated offset, all six
strict faces, double truncation, short wrapping, negative fractions, the plant
rotation with and without its matrix and a disabled shape; 48 cases are seeded
random. The five `sequences` model the `MRColl_lw_ptr`/`MRColl_matrix_ptr`
cache: each check names a `frame_key` (`map`/`live`/`lw` identity) and a
`matrix_key` (`[]` for none) and expects the `status`, the `rotation` used, a
`stale` flag and `local`. They cover mutated contents under the same keys
(stale rotation, fresh translation), another frame or matrix in between, a
matrix-to-none change and a disabled primitive that leaves the cache alone.

committed file; `--write` regenerates it. `test_entity_animated_primitives.gd`

The plant is created on cel 0 with the default step flag (`stepping` true at
tick 0). WAITING clears the step flag and enters WAITING_TO_SNAP on the tick
the distance is below 356. `if (!(timer--))` fires when the timer was 0 before
the decrement, so the snap starts `snap_time+1` ticks after the entering tick
and the timer then reads −1. The snap sets the step flag and `snap_timer`
15; SNAPPING enters DELAY on the tick whose update sees the last cel. The
action is not one-shot: the cel wraps to 0 on that tick and keeps cycling
through DELAY. DELAY lasts `snap_delay+1` ticks, then sets cel 0, clears the
step flag and returns to WAITING, which can retrigger on the next tick. SNAPPING
and DELAY play the snap sound whenever `snap_timer` is 0 (then reload 15),
else decrement it, so repeats come every 16 ticks, including the tick DELAY
ends. The sound gate is not an input: `PlaySoundDistance` measures the same
entity origin as `DistanceToFrogger(COORD_Z, 0)`, so a sound is listed only when
`30 > isqrt(distance)` for that tick's distance; 9999999 (no frog) never plays.
The single-player checkpoint and game-over suppressions are not modelled.

The rope bridge is created on cel 0 with the step flag clear, one-shot set and
collision on. Each observed hit increments the u8 count; reaching
`hops_before` (0 triggers on the first hit) loads the wait. `if
(current_wait-- <= 0)` on the u16 fires only when the wait was 0, after
`fall_delay+1` updates, leaving 65535. The fall tick sets the step flag, turns
collision off and drops a rider (`frog_fall` echoes `rider` on that tick
only). Hits in WAITING_TO_FALL or FALLING change nothing.

`mushroom_bounce` covers a frog that is not carried by an entity
(`FROG_ON_ENTITY` clear, `fr_entity` null, one player, no powerups). `centred`
holds the BOUNCY branch's result: `fr_pos` with X/Z replaced by the entity
translation `<<16`, the `lw` translation (`fr_pos>>16`), the grid cell and
`forbid` (the entity becomes `fr_forbid_entity`). The jump uses controller
directions `(N+i)&3`, so `direction` always equals the frog's direction and
`jump_direction` (`direction − controller_n`, possibly negative) is masked by
`&3`. The target is two cells away. When it leaves the grid, the bounds loop
moves it two further cells outward (`inside` false, `square` null). Inside the
grid, the bounce-wall tests run first: north checks the current square's
`BOUNCE_WALL_N`, south the target stack's, east the current square's
`BOUNCE_WALL_E`, west the target stack's. A hit gives `result` `cobweb` with
`user_data` [x, z]. Otherwise the first usable square with `y ≥ y1` (rise up to
0x7fff) or `y1 − y ≤ 0x100` lands (`to_land`); else the last usable square at or
below the frog from the top of the stack; else the forced jump keeps
`square = first index − 1` (the stale pointer C leaves); an empty stack gives
null. Water is not tested. `target` is [x, z] only: `JumpFrog` does not write
the target Y here. With `to_land`, `fr_y` is the square height and
`vy = ((fr_y − t[1])<<16)/16 − 0x800000`; otherwise `fr_y = t[1]` and
`vy = −0x800000`. `vx`/`vz` are `((target<<16) − fr_pos)/15` truncating. `flags`

family.

`door_bounce_back` reverses the frog's direction (N→S, E→W, S→N, W→E) and steps
one cell back. The callback loop never advances its square pointer, so only
the first square of the target stack counts. An empty stack or an unusable first
square gives `happened` false and `branch` `none`; every other field is then
null, 0 or false. In user mode (`mode ≥ 0x100`), `branch` `user` keeps the
direction, mode and translation. It sets the cell, `count` 6, `target`
[x, height, z] and `velocity` `((target<<16) − fr_pos)/6` per axis. It also
writes `cr_count = 4` through the door's runtime pointer (`runtime_count`).
The JUN_OUTRO_DOOR entity book allocates no runtime, so the port must not copy
that write. Otherwise `branch` `normal` adds `JUMP_TO_LAND|JUMP_FROM_COLLPRIM`
(65600), sets `mode` 1, `count` 6, `forbid`, the reversed `direction`,
`old_y = fr_y` and `target` [x, null, z] (Y unchanged). It computes
`vx`/`vz = ((target<<16) − fr_pos)/6` and
`vy = ((fr_y − t[1])<<16)/7 − 0x380000`, truncating signed division. Finally it
pushes `translation` t[0] += vx>>15 and t[2] += vz>>15 (arithmetic). The
`THEME_SWP` deadly-form test does not run outside Swamp.

The squirt counts its delay down once: `if (timer > 0) timer--` else
FALL_PREPARE, so delay 0 or negative prepares on tick 1. FALL_PREPARE divides
`(target<<16) − (t<<16)` by `drop_time` (truncating) and requests ACID_DRIP
when `DistanceToFrogger(entity, 0, 0)`, measured at the reset translation, is
below 1536. FALLING adds `velocity>>16` and then tests `if (timer-- <= 0)`, so
it moves `drop_time+1` times; the last move is replaced by the authored
translation and the squirt returns to FALL_PREPARE, never to WAITING. A
negative drop time reverses the velocity and resets after one move.

The crusher and press load the s16 delay into a u16 timer, so −1 waits 65536
updates; `if (!timer--)` enters the moving action `delay+1` updates after
creation and the timer reads 65535 from then on. Neither returns to waiting.
Each moving update adds `±(speed>>8)` on the authored axis (crusher N/S on Z,
E/W on X; press on Y) and flips the direction with `!direction` once the
translation passes the outer bound (`origin ± distance`) or returns past the
authored origin, using strict comparisons. Other direction values never move.
A negative speed moves away from both bounds forever. The crusher decrements
a non-zero u16 `cr_count` at the start of every update, before the timer;
`callback_ticks` set it to 5 before that tick's update, as a callback hit in
the previous frame would. Creation starts CRUSH_AMB (crusher) or MACHINE
(press) as a moving sound with radii 768/1280. Only the press's return flip
makes a sound: FROG_CRUSH when the entity carries the frog, otherwise
SWP_CRUSH_HIT when the distance at the new translation is below 1536.

`swamp_crusher_callback` covers the `THEME_SWP` branch. A non-zero `count`
returns at once (`debounced`): nothing changes and the deadly test does not
run. Otherwise `cr_count` becomes 5. A frog with X or Z velocity takes
`branch` `velocity`: the cell comes from the lw translation, not the stored
cell. The larger absolute axis wins and a tie goes to Z; positive X bounces
west, negative X east, positive Z south and negative Z north. Zero X/Z velocity
takes `branch` `default`, the stored-cell facing reversal of
[Jungle entities](#jungle-entities); a direction outside 0–3 keeps itself
and the cell. The first-square-only bounce matches `door_bounce_back`. The
user-mode branch writes `cr_count = 4`, which a Swamp crusher keeps. Afterwards,
when the FORM has FORM_DATA, the pushed frog translation minus the crusher's,
as MR_SVEC, is multiplied by the transposed crusher rotation (`local`). X and Z
must lie strictly inside `ofs .. ofs + num·256` and Y within `height ≤ y ≤
max_y`. The square `((z−zofs)>>8)·xnum + ((x−xofs)>>8)` kills with SQUISHED
when it is DEADLY. `FrogKill` clears the velocity unless the frog is JUMPING
with JUMP_TO_LAND (`velocity_after`). Already-dying frogs are outside this
family.

The rat is created in RESTART at its start target. `resolved` holds
`ENTSTRSwpCreateRat`'s values: `run_speed = speed/30`, phase times
`isqrt(dx²+dy²+dz²)/30` (the run divides by `run_speed`), `(d<<4)/time`
velocities, the unused XZ distances and `2048/time` sine steps, all
truncating. Each jump sets `pos.y = previous_y + vy`, stores it, then
subtracts `((rsin(sine)·250)>>12)<<4` before advancing the sine. INIT_FIRST_JUMP
and the run's last tick set the one-shot JUMP action; INIT_ROLL sets one-shot
ROLL for 24 ticks; RUN loops. The u16 count is compared with `==`, so a
negative run time never ends the run. The first JUMP2 update with
`(pos.y>>4) ≥ −255` splashes once: colour scale (128,128,128), ambient
(255,0,255). RESTART resets the position, colour scale (128,128,128), ambient
(255,255,255) and the splash flag. The translation is `pos>>4`.

`ENTSTRSwpCreateWeir` overwrites the authored rotation with `MRRotMatrix(0,
0, 1024)`, `[0,−4096,0, 4096,0,0, 0,0,4096]`, and keeps the translation.
`script_swp_weir_rotate` then adds 0x20 to the X angle each update, building
`RotX(angle)·weir` (MulMatrix0, `(Σ)>>12`). The update that reaches 0x1000
stores angle 0, and an all-zero angle set leaves the previous matrix in place.
The next update only runs `ENDLOOP` (a break), so it keeps that stale matrix
too. The cycle is 130 updates.

`script_registers` `setup` cases read `count` little-endian MR_LONGs at the

Retail trigger records are 56 bytes: `ENTSTR_TRIGGER`'s trailing
`et_frame_count` is absent and never read. Types 0–3 are FREEZE, REVERSE, START
and BEGIN. A record shorter than 56 bytes or a type above 3 is outside the
source enum (`source_defined` false) and the port rejects it; frozen C would
pause the targets and only forbid on contact for such a type. An id of −1 marks
an unused slot. Every other s16 id converts to the u16 lookup parameter, so
−2 finds unique id 65534.

`ENTSTRCreateTrigger` sets `et_first_time`. The first `ENTSTRUpdateTrigger`
sets ENTITY_NO_MOVEMENT and clears PATH_RUNNER_ACTIVE on each listed live
target; ids with no live entity are skipped, and later updates do nothing.
Targets start as mapload creates them: a path runner is ACTIVE exactly when the
entity lacks ENTITY_NO_MOVEMENT. `TriggerEntityCallback` walks the ten ids in
order, so a repeated id toggles twice. FREEZE and START toggle NO_MOVEMENT and
set ACTIVE to its inverse. BEGIN clears NO_MOVEMENT and sets ACTIVE only on a
stopped target. REVERSE clears PATH_RUNNER_BACKWARDS in both branches of its
`if`, so it never reverses a runner; the retail code at 0x42BA00 merges the two
branches into one clear. This disagrees with the case name and comment, and
frozen behaviour wins. A listed id that is not live, or REVERSE on a pathless
target, dereferences null after a compiled-out assert (`source_defined` false);
the port rejects the contact. Every defined callback then sets
`fr_forbid_entity` and FROG_JUMP_FROM_COLLPRIM. It has no debounce.

MOVING and MOVING_PLATFORM payloads are the 12-byte `PATH_INFO`.
`VOL_TRIGGERED_PLATFORM` appends a u32 initial movement at 12, read as 0 when
absent. `ENTSTRUpdateMovingPlatformMOF` plays the chain sound only under
THEME_VOL (10). The `platform_payload` path fixture is two LINE segments of the
stated length. The port rejects nonzero `pi_pad`, so the cases keep it zero.

`UpdateSkyLand` runs once per `GameUpdateLogic` when the game is not paused,
after `UpdateEffects`, and acts only under THEME_SKY (8). When `Game_timer &
0x7f` is zero it chooses a new acceleration. Outside ±0xB00 on X or Z (by
`pos>>16`), the acceleration is `−pos>>16` per axis, with no draw. Otherwise it
is `(rand()&0x3ff, 0, rand()&0x3ff)`, drawing X then Z from MRrand
(`seed·0x41c64e6d + 0x3039`, u32, returning `(seed>>16)&0x7fff`). Either
choice is normalised and shifted left by 3. Otherwise, when `(Game_timer & 0xff) <
0x60`, it adds the acceleration to the velocity; otherwise each velocity axis
becomes `(v>>5)·31`. The position then adds the velocity, and X and Z are
clamped to ±0x10000000 on every call. The drawn translation is `pos>>16`.
`LevelStart` clears all three vectors at level start, death and checkpoint
restart. Rows run with the timer advancing once per tick unless `timers` lists
the timer each tick sees. A held timer that is a multiple of 128 draws on every
held tick. `MRNormaliseVEC` is libgte `VectorNormal`, absent from the vendor
tree; the generator uses the rounded float convention of
`make_golden_paths.py`, whose zero vector stays zero. `SYSTEM.H` defines
`MR_KEEP_SYSTEM_RAND`, so `rand()` there names the C library function; this
family keeps the project's shared MRrand stream used by the other `rand()`
consumers.

`Game_timer` is a u32 that nothing resets. `GameMainloopPlayUpdate`, the
GAME_MODE_LEVEL_PLAY mainloop function, is its only increment. It runs once per
main-loop frame after that frame's logic updates. The PC loop runs up to
`MAX_LOGIC_LOOPS_PER_RENDER` (3) `GameUpdateLogic` calls per frame, all seeing
the same timer. The start, trigger-collected, frog-died and fast-start
functions never increment it. The cases drive single-start frames, level-play
frames, a u32 wrap and post-`LevelStart` catch-up frames of two and three
logic ticks.

`sky_script_registers` assembles `script_sky_helicopter` (2 registers),
`script_sky_helium_balloon_waiting` (2), `script_sky_rubber_balloon_waiting`
(3) and `script_sky_homing_bird` (`SCRIPT_SKY_BIRD`, 2: speed and range),
together with the balloon scripts they branch to. `PREPARE_REGISTERS
(sizeof(MR_MAT), n)` reads n little-endian s32 words after the 32-byte matrix.
Longer payloads keep the same values. A payload one byte short reads outside
the entity data (`source_defined` false).

`pc-retail-v3.0e/sky_entities.tsv` comes from
`python3 -B tools/make_golden_sky_entities.py --data-dir <game-folder>`; it
verifies by default and rewrites with `--write`. It reuses the Swamp retail
readers, script-register walk, collision-primitive rows and `fields` encoding.

- `entity` rows cover every Sky-form entity of SKY1–SKY4 (maps 668–671 and
  703–706) with the Swamp common fields plus `root_script` (`-` without a
  script), `register_offset` and `registers`. Path kinds add the `PATH_INFO`
  fields and `path_pad`; MOVING_PLATFORM adds `initial_movement` and
  `chain_sound`. Matrix kinds add `matrix`; the trigger adds `trigger_type`
  and `trigger_ids`. The generator requires the executable's prepared register
  counts to equal the frozen `ent_sky.c` counts above.
- `form_grid` rows give each FORM a Sky-form entity uses, with stored and
  runtime `max_y`. `mapload.C` keeps the stored value without a model, uses
  0x7fff for THICK_FORM and 0x100 for UNIT_FORM, and otherwise uses bounding-box
  vertex 7 Y: the first part's for static models, the animation's global box
  for animated ones. Some FORMs have no FORM_DATA and unrelated stored header
  values; the rows keep them as stored.
- `census` rows count every map entity by entity name, form and entity flags.
- `actions` rows give every animated or flipbook Sky model's action lengths;
  `collprim` rows give the magical balloon's primitive, the only Sky model
  with one.
- `callback` rows give every Sky form's collision and bonus callbacks and root
  script, keyed by local form index. Only SKY_FROGGERS_MAGICAL_POPPING_BALLOON
  and Volcano's VOL_SWITCH use 0x42BA00 `TriggerEntityCallback`; its code
  identity is in `form_callbacks.json`.

moving-platform operands, registers and root scripts with every entity row. It

through whole-map setup with every entity, no `unknown_behavior`,
`invalid_payload` or `incompatible_callback` diagnostic and census-derived
