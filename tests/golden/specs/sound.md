# Logical sound and pickup facts

The logical families verify gameplay-visible allocation, RNG and lifetime
decisions without rendering audio. [Sound playback](#sound-playback) pins the
presentation rules that turn committed voices into audible players.

- `synthetic/bonus_fly.json`: generic pickup reward IDs, source frame narrowing,
  bobbing, stopped movement, active/absent voice pitch gates and ordered RNG.
  Reproduce with `python3 tools/golden/make_golden_bonus_fly.py`.
- `synthetic/sound_bank.json`: independent synthetic Windows header rows,
  present/absent spans, 8/16-bit sample counts and edited rates. Reproduce with
  `python3 tools/golden/make_golden_sound_bank.py`.
- `synthetic/logical_sound.json`: independent frozen C/native single, repeat and
  looped voice lifetimes; first-update protection, pitch bend, allocation
  pressure, identifiers and RNG. Reproduce with
  `python3 tools/golden/make_golden_logical_sound.py`.
- `pc-retail-v3.0e/sound_tables.json`: executable bank/group/sample/music-pitch
  metadata, initialization code SHA-256 and Windows bank duration facts.
  Reproduce with `python3 tools/golden/make_golden_sound_tables.py --data-dir <retail>`.
  The independent Python reader uses supplied EXE/MWD bytes and writes only
  decoded facts and hashes. No retail bytes belong in the repository.

Focused checks use the prescribed test wrapper with `-gselect=bonus_fly`,
`-gselect=sound_bank`, `-gselect=logical_sound`, or `-gselect=retail_sound`.
For each family, change one expected scalar, require a failing assertion,
restore the original facts and rerun. Keep logs and saved assets external.

The generic fly's moving object initially has no voice. Voice allocation uses
source group order and available slots; proximity alone is insufficient to
permit pitch RNG. Logical moving owners are copied with the gameplay candidate,
so later failure cannot consume random draws or publish allocations. Additional
component checks cover latest-created moving-object priority, radius exit,
reallocation, stale voice-generation tags and detached mutation.

## Sound playback

`synthetic/sound_playback.json` is generated by
`python3 tools/golden/make_golden_sound_playback.py` (`--write` regenerates; the
default verifies reproducibility). The independent Python reads frozen
`MR_SOUND.C`/`.H` (`MRSNDPlaySound`, `MRSNDUpdateSound`,
`MRSNDCreateMovingSound`, `MRSNDUpdateMovingSounds`), `sound.c`
(`PlaySoundDistance`, `PlayMovingSound`), `FROG.C` (listener target), the
native backend `mr_stub_snd.c` (step and bend) and `mr_stub_math.c`
(`ApplyTransposeMatrixLV`, `VectorNormal`), plus FrogLord's Windows header for
8-bit signedness. Line citations live in the generator's docstring.

| Group | Inputs → expected | Rules |
|---|---|---|
| `pitch` | `note`, `fine`, `bend` → `ratio`, `bend_ratio`, `pitch_scale`, `rate_hz`, `base_step_16`, `step_16` | 11025 Hz at note 60, 44100 Hz output, ±2 semitones about bend 64; steps round half up with a floor of 1 |
| `volume` | `source`, `listener`, row-major 4.12 listener `matrix`, `min_radius`, `max_radius`, `min_volume`, `max_volume` → `radius`, `clamped_radius`, `angle`, `volume_12`, `pan_x`, `left`, `right`; `fixed` rows → `left`, `right` | u16 radius from components `>> 4`; sine fade between the radii; transpose-applied rounded unit vector, `pan_x` clamped 0–8191, levels `>> 18` |
| `pcm` | synthetic body rule and digest; rows `present`, `offset`, `size`, `bits` → `error` (`absent`, `span`, `partial`) or `frames`, widened `samples`, list `digest` | 16-bit signed little-endian; 8-bit unsigned widened as `(u − 128) << 8`; empty spans are rejected |
| `loop` | `flags`, `frames` → `wraps_in_mixer`, `retriggers`, `loop`, `loop_begin`, `loop_end` | SINGLE (2) plays once; REPEAT (4) is re-keyed by `MRSNDUpdateSound` and LOOPED (8) wraps the whole sample, so both loop forward over every frame |
| `voice_diff` | `sample_flags`; per sequence and tick, sparse `before`/`after` voice slots (`slot`, `sample`, `identifier`, `note`, `fine`, `pitch`, `playing`, `killed`) → ordered `actions` (`start`, `bend`, `stop`, `release`) | see below |

A fixed sound (`PlaySoundDistance` and other `MRSNDPlaySound(…, NULL, …)`
calls) uses `si_max_volume` on both sides. A moving sound reaches its maximum
volume at or inside `min_radius` and its minimum at `max_radius`. Rows past
`max_radius` (`in_range` false) still record the clamped formula; the logical
update kills those voices. Centred sound, including a zero vector, gives each
side half the volume. The `volume` group always applies fade and pan, the
flags every `MRSNDCreateMovingSound` caller keeps. Doppler stays in the logical
model as a bend.

Voice diffs compare each committed tick with the one before it, slot by slot
in ascending order, and track the player each slot last started. A voice with
a sample, not killed and playing, whose predecessor had no sample or another
`identifier`, emits `start` with its sample, identifier, note, fine and pitch.
A tracked voice whose `pitch` changed emits `bend`. A tracked looping voice
(REPEAT or LOOPED) that stops playing emits `stop`. When the tracked voice is
killed, replaced or retired, a looping or killed voice emits `stop`. A one-shot
that ended on its own emits `release`, so its player plays out. A REPEAT
retrigger keeps its identifier and stays playing, so it emits nothing.
`test_sound_playback.gd` drives `SoundVoiceView` outside the tree and checks
tracked identifiers and pitch scales after every tick.

The focused check is `-gselect=sound_playback`. Break one scalar per group,
require its assertion to fail, then restore it.
