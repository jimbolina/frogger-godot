# P7 validation

Validation uses Godot 4.5.1, isolated writable user data and hidden awaited
processes. The selected behavior target is the frozen C port at 30 Hz;
[original retail timing](../reference/pc-timing.md) remains separate unmeasured
compatibility evidence. Final retail and asset-free suites pass against the
restored, hash-pinned candidate. All checks below ran on 2026-10-01.

## Independent facts and source boundary

[GRID](../reference/grid.md) covers all 78 retail map/detail packets with text
scalars and digests. Synthetic original and odd-grid queries agree with linked
frozen C objects. The [terrain coverage table](../reference/terrain-movement.md)
records source dispatch, arithmetic, input, collision and death coverage;
[animation](../reference/frog-animation-control.md) and
[camera](../reference/gameplay-camera.md) define their component state.
Expected facts come from independent Python implementations checked against
actual unchanged C objects, never from GDScript output.

The [integrated corpus](../../tests/golden/specs/integrated-terrain.md) contains
1,464 source component records in Control, Move, Collide, Camera, animation
scripts and pose order. Five public phases compare 39 represented fields.
Shared selected camera/animation RNG draws are checked, including reset and
copy detachment. Audio, score-system mutations, entities and renderer/effect
factory behavior remain explicitly omitted at the adapter boundary; this is
not a full-engine state-parity claim. Link inputs, source/object hashes and
repeat-run stdout hashes are retained outside the repository.

The Python complete-trace comparator regression checks pass: missing/reordered
phases, identical truncation, error records and post-completion records fail.

in order. Execution must reach metadata `tick_limit` or end with explicit
completed state; a zero-tick limit permits metadata only.

ground children, with the replaced generated mesh's weak reference cleared
after queued frees. Three retail frog attach/detach cycles share one bundle
between setup and drawing and clear both old bundle and mesh weak references.

zero ground children and closes the owned source while borrowed data remains
open. These are object-lifetime checks, not memory benchmarks or invented limits.

## Render schedules and foreground geometry

The final hash-pinned schedule batch passed all twelve comparisons:
four fixtures at scheduled render rates 30,
60 and 144, with 120/120/600/380 public phase records. Each rendered full JSONL
trace and metadata exactly matched its headless run, and each passed the
independent 39-field C comparison. These are scheduled-delta tests, not a host
frame-rate measurement. Source, tools, scenes, project, reference and scenario
hashes remained unchanged throughout the batch.

[Foreground projection evidence](../reference/gameplay-projection.md) compares
start, airborne and landed poses. Each has 227 raw vertex facts and 207 source-
visible landmarks; all declared individual bounds pass. Both silhouette
directions have zero pixels beyond the declared radius of three pixels.
The captures were inspected. Placement, orientation and geometry agree;
the candidate is visibly brighter and flatter in color. Accurate source
animated per-part lighting is missing from the current renderer, so lighting
and color parity are not claimed. The roadmap retains that graphics follow-up.
